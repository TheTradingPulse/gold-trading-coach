# TradingPulse Canonical Architecture

The working dashboard remains the production presentation entry point during
consolidation. Research generations are not application versions; they are
sources of validated contracts and evidence.

## Current authority

- Live structure: `MarketState` and `SetupCandidate`.
- Deterministic levels: `trade_plan_engine`.
- Execution readiness: `execution_lifecycle_engine`.
- Live evidence: fail closed until the V5/V6 parity adapter passes validation.
- Historical source: immutable Databento history and the V5 warehouse.
- Professional-zone research: V6 reference database.
- Outcome targets: 1R through 20R with conservative ambiguity treatment.

## Promotion rule

No research result may reach the dashboard unless it has:

1. Point-in-time feature availability.
2. Production/replay setup parity.
3. Mutually exclusive first-touch outcomes.
4. Contract-specific transaction costs.
5. Walk-forward and concentration stability.
6. A final holdout not used to choose the policy.
7. A frozen policy manifest and version.

## Phase boundaries

Phase 1 archives clutter and installs this registry. Phase 2 builds canonical
contracts and parity tests. Phase 3 replaces the stale Backtest backend. Phase 4
adds a read-only V5/V6 evidence adapter. UI extraction happens only after parity.
